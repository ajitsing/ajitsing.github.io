SAML request debugging guide

What is a SAML AuthnRequest?

A SAML AuthnRequest asks an Identity Provider to authenticate a user and return a signed SAMLResponse to your Service Provider ACS URL. The request is XML wrapped as SAMLRequest on redirect or POST.

HTTP-Redirect vs HTTP-POST

HTTP-Redirect compresses the XML with DEFLATE, Base64 encodes it, and places it in the query string. HTTP-POST Base64 encodes the XML without DEFLATE and auto-posts a form. This decoder auto-detects both.

Typical SSO failures at the request

  • Wrong AssertionConsumerServiceURL in the SP metadata versus what the IdP expects.
  • Missing or mismatched Issuer entity ID.
  • Corrupt DEFLATE or double URL encoding on the SAMLRequest parameter.

SAML Request Decoder FAQ

How do I decode a SAMLRequest from a redirect URL?

Paste the full URL or the SAMLRequest= value. The decoder URL decodes, Base64 decodes, and inflates DEFLATE when needed.

What is HTTP-Redirect binding?

It sends SAML in the query string using DEFLATE, Base64, and URL encoding. It is common for SP-initiated SSO to Okta and similar IdPs.

Is my SAML request uploaded?

No. Decoding runs locally in JavaScript. Nothing is sent to a server.

How do I decode SAMLResponse?

Use the SAML Response Decoder to inspect assertions, attributes, and certificate signatures.
